# 23: 知识库对话与证据边界标注

**What to build:** 用户在全局 Agent 侧栏中跨来源文档与笔记提问，对话式地探索积累的知识。回答的每个段落都带来源归属：有库内依据的段落归属为来源，模型自己补充的段落归属为 AI，用户可见文案分别是「有来源支撑」与「模型补充」。这不是第二套标签，而是全系统那一套三值词汇在对话层的取值——User 不会出现在回答里，因为回答不是用户写的（ADR-0004）。证据段落可以跳转到精确出处去核对。模型在有帮助时可以使用通用知识，但流畅的表述不会被误认为库内已有的依据。

稿件何时进入检索语料由 ADR-0011 规定，本票不断言：稿件实体到票 24 才存在，在这里断言「试写稿未被召回」会因为语料里根本没有任何稿件而恒真。

**Blocked by:** 12, 18

**Status:** done

**Starting failing test:** 就一个库内有证据、同时需要通用知识补充的问题提问，断言回答分段带归属、来源段落的归属值与 AI 段落的归属值取自同一套三值词汇、来源段落可跳回精确出处；再在一份来源文档尚未索引完成时提问，断言界面明确告知结果基于部分索引。

**Demo acceptance:** 需要。证据与补充的视觉区分是否一眼可辨，只能人看。

- [x] 用户可以跨来源文档与笔记提问并得到回答
- [x] 回答的每个段落带三值来源归属中的来源或 AI，存储的是三值标签本身，界面文案「有来源支撑」与「模型补充」只是它的呈现，任何代码都不依据文案分支（ADR-0004）
- [x] 回答段落的归属值不可能为用户，对该值的处理是拒绝而不是渲染
- [x] 证据段落可链接跳转到精确出处
- [x] 缺乏库内依据的论断被标为 AI 归属，不伪装为证据
- [x] 模型在有帮助时可以使用通用知识，答案不被人为限制在库内
- [x] 结果基于部分索引时对用户明确可见，与检索侧的索引状态标注一致
- [x] 全局 Agent 侧栏在书库/阅读、思想、创作三个空间都可用
- [x] 在阅读时使用侧栏不会替换或遮挡阅读界面，阅读位置在对话前后不变
- [x] 断网或模型不可用时对话明确失败，其他功能不受影响
