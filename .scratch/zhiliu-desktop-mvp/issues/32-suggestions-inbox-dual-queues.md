# 32: 建议收件箱与双队列

**What to build:** 主动发现的结果汇聚到应用内的建议收件箱，而不是打扰式的系统通知。收件箱按主题来源分为「你的思想线索」与「从书库发现」两个队列，来源本身由证据推导，因此语料里的观点不会被表述为用户自己的信念。

「语料观点不被当作用户信念」这句承诺无法直接断言——它是语义判断，写成断言只会恒真。本票把它拆成两条可断言的机制：队列归属必须等于推导出的主题来源而不是另一套独立标记；书库发现条目的展示文案由固定模板生成，模板中不出现第一人称主张句式。措辞本身的说服力交给演示验收。

书库发现可以分析全部导入内容，包括未读材料。

**Blocked by:** 29

**Status:** ready-for-agent

**Starting failing test:** 制造一个思想线索与一个书库发现，断言它们分列两个队列、队列归属逐一等于各自主题的推导来源、各自证据可跳转，且书库发现条目的文案来自固定模板并不含第一人称主张句式；再把该书库发现主题补到三条思想笔记，断言它自动移入思想线索队列。

**Demo acceptance:** 需要。两个队列的措辞是否真的传达了信念边界，只能人判断。

- [ ] 收件箱按主题来源分为「你的思想线索」与「从书库发现」两个队列
- [ ] 队列归属直接来自推导出的主题来源，不是另一套独立标记；测试逐条比对二者一致
- [ ] 书库发现条目的展示文案由固定模板生成，模板中不出现第一人称主张句式
- [ ] 主题来源变化时条目在两个队列之间自动移动
- [ ] 书库发现队列可分析全部导入内容，包括未读材料
- [ ] 每条建议展示其证据并可跳转到来源
- [ ] 建议只在应用内呈现，不使用系统级打扰通知
- [ ] 用户可以采纳或忽略建议，状态持久保存
