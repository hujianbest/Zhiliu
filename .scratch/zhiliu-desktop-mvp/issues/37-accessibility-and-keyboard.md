# 37: 无障碍与键盘可达性

**What to build:** 所有核心流程都能仅用键盘走通，焦点始终可见，快捷键可被发现而不依赖记忆；屏幕阅读器能读出有意义的控件名称；来源归属在不感知颜色的情况下依然可区分。速度不以隐藏命令为代价，学习性不以牺牲效率为代价。

「每一步焦点可见且控件有可读名称」偏存在性，一个把所有控件都加上名称属性的空实现就能通过。本票因此额外要求一条真正会红的行为断言：核心流程的键盘路径步数有明确上限，且完整 Tab 序列中不出现焦点丢失。

**Blocked by:** 31, 34

**Status:** ready-for-agent

**Starting failing test:** 仅用键盘走完导入、阅读、捕获、检索、写作、导出的核心流程，断言每一步焦点可见且控件有可读名称；断言每个流程的键盘步数不超过为它记录下来的上限；断言在完整 Tab 序列中焦点从不落回 body。

**Demo acceptance:** 需要。这张票的本质就是人的可用性，必须人走一遍。

- [ ] 所有核心流程可以仅用键盘完成，焦点始终可见
- [ ] 每个核心流程的键盘路径步数上限被记录下来，超出即测试失败
- [ ] 完整 Tab 序列中不出现焦点丢失，焦点不落回 body
- [ ] 快捷键可被发现，有可见入口或命令列表，不依赖记忆
- [ ] 屏幕阅读器能读出有意义的控件名称
- [ ] 来源归属在不感知颜色的情况下依然可区分
- [ ] 每个带快捷键的动作都有对应的可见控件
