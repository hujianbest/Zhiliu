# 21: Agent 预算与用量报告

**What to build:** 用户为后台工作设置日与月的 Token 上限和请求数上限，并能看到区分交互式与后台的累计用量，因此即使不清楚服务商定价也能理解活动量。后台预算耗尽时主动工作干净暂停，不影响用户主动发起的请求，除非用户自己配置了共享硬上限。服务商不返回用量时，Token 由本地估算并明确标注为估算值，请求数照常精确计数——spec 已要求在定价未知时仍能理解活动量，请求数是唯一在任何服务商下都精确的口径，因此它是兜底约束而不是补充信息。

区分交互式与后台的判定依据必须先落定，否则「后台暂停而交互式仍可用」这条核心断言无法构造：由用户直接发起的调用是交互式，由 Agent 自己排期发起的是后台，两者在生成留痕里各自可辨。

**Blocked by:** 18

**Status:** ready-for-agent

**Starting failing test:** 把后台预算调到极小，用票 18 的手动入口发起一个由 Agent 排期的后台任务，断言后台工作在预算耗尽后暂停、暂停状态可见，而用户直接发起的请求仍然成功；再用不返回用量的假服务商调用一次，断言 Token 被记为估算值且请求数精确加一。

**Demo acceptance:** 需要。用量报告是否让人看懂自己花了多少，只能人判断。

- [ ] 交互式与后台的判定依据被明确记录：用户直接发起为交互式，Agent 自行排期发起为后台，二者在生成留痕中可区分
- [ ] 用户可配置后台工作的日与月 Token 上限及请求数上限
- [ ] 用量报告区分交互式与后台调用并展示累计值
- [ ] 服务商未返回用量时本地估算 Token，并在界面上明确标注为估算值
- [ ] 请求数在任何情况下都精确计数，作为定价未知时的兜底约束
- [ ] 后台预算耗尽时主动工作干净暂停，暂停状态对用户可见
- [ ] 暂停不阻塞用户主动发起的请求，除非用户配置了共享硬上限
- [ ] 新的一天或新的一月到来后后台工作可继续
