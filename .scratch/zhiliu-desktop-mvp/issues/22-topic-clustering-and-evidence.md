# 22: 主题自动聚类与证据展示

**What to build:** Agent 把来自不同来源文档的笔记聚成命名主题，让反复出现的想法跨来源变得可见。每个主题的来源由证据自动推导：积累到至少三条思想笔记即为思想线索，否则为书库发现，这个划分没有中间值（ADR-0002）。主题展示自己的依据，用户因此可以判断这个模式是否真实存在。分析未读内容不会把来源文档标记为已读——票 07 定义了这条规则，本票是它唯一能被真正断言的地方，因为模型分析能力到这里才存在。一次 Agent 组织操作成组提交，可以在历史时间线中作为一个操作查看。

**Blocked by:** 07, 11, 18

**Status:** done

**Starting failing test:** 用跨两份来源文档的笔记素材跑一次聚类，断言产生带证据链接的主题、未读来源文档的阅读状态在分析前后未变、且这次组织操作在时间线上是一个可回滚的操作。

**Demo acceptance:** 需要。主题命名是否贴切、分组是否说得通，只能人判断。

- [x] Agent 可以把跨来源的笔记聚成主题并给出可读的名称
- [x] 主题是持久化的用户所有实体，重启后仍然存在
- [x] 主题来源由证据自动推导，阈值为三条思想笔记，与写作就绪是同一个条件（ADR-0002）
- [x] 少于三条思想笔记的主题一律为书库发现，不存在第三种状态或待定值（ADR-0002）
- [x] 主题来源在任何界面上都不可手动设置
- [x] 思想线索展示支撑它的思想笔记，书库发现展示来源证据
- [x] 证据条目可跳转到笔记或来源的精确出处
- [x] 测试断言模型对来源的分析或摘要不改变其阅读状态，未读来源在分析后仍为未读（承接票 07 的规则）
- [x] 一次 Agent 组织操作成组提交，在历史时间线中呈现为一个操作
