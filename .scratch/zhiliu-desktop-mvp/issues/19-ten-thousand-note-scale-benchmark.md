# 19: 一万条笔记规模基准与性能预算

**What to build:** 在约 10,000 条原子笔记的知识库上，于 8GB 无独显的参考机型画像下测量启动时间、增量索引时间、检索延迟与空闲内存，并把结论固化为明确的性能预算，让系统作为长期第二大脑仍然可用，日后回归会被测试挡住。10,000 只计原子笔记；来源文档正文分块的数量级要高得多——ADR-0006 给出的推导是约二十万块，笔记在其中只是零头——因此分块规模单独估算、单独设预算，避免混成一个数字之后预算失去意义。

预算的上限值必须先在本票写死，不能留给实现期自行确定：实现者完全可以先跑一遍再把预算设成刚好通过，那样测试永远是绿的，规模回归就永远不会被挡住。下面四个数是本票给定的上限，实现期只允许把实测基线记录下来，不允许放宽上限；确实需要放宽必须先经独立评审。

依赖票 11 的理由是自动 Git 提交会计入启动时间与增量索引耗时，不测它就等于测了一个用户不会遇到的配置。

**Blocked by:** 11, 12

**Status:** done

**Starting failing test:** 生成一万条原子笔记加二十万块来源文档分块的知识库，断言冷启动到可交互不超过 6 秒、单条笔记从保存到可被检索命中不超过 1 秒、检索 P95 延迟不超过 1 秒、稳定运行后空闲内存不超过 800 MB。

**Demo acceptance:** 不需要。四项预算全部由断言覆盖，且上限值已在本票写死。

- [x] 可以生成约 10,000 条原子笔记的测试知识库
- [x] 10,000 的口径只计原子笔记，不含来源文档正文分块
- [x] 来源文档分块的规模按 ADR-0006 的推导单独估算为约二十万块，并有自己的一组性能预算
- [x] 在 8GB 无独显参考机型画像上测量启动时间、增量索引时间、检索延迟与空闲内存
- [x] 四项预算的上限为：冷启动到可交互 ≤ 6 秒、单条笔记从保存到可被检索命中 ≤ 1 秒、检索 P95 ≤ 1 秒、空闲内存 ≤ 800 MB；超出即测试失败
- [x] 实测基线值被记录在案，但记录基线不得用于放宽上述上限

- [x] GPU 加速可以改善处理速度但不是必需
