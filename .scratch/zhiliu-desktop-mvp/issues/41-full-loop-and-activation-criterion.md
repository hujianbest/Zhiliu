# 41: 完整闭环贯通场景与三十分钟激活判据

**What to build:** spec 的主线幸福路径场景，作为一条端到端断言存在：首次运行配置 → 导入材料 → 渐进索引 → 阅读选中 → 捕获 → 主题发现 → 提案审阅 → 正式写作 → 归属检视 → 干净导出。票 28 穿过了前半条链，这张票穿过整条，并承接 spec 自己写明的 MVP 激活判据——新用户在三十分钟内从导入材料走到一份有来源支撑的稿件。在这之前，全部四十一张票可以逐条打勾而这个闭环从未被走通过一次。

三十分钟这个数不能用一份微型素材来敷衍：素材过小的话任何实现都能通过，断言就成了装饰。因此场景必须用三份真实体量的来源文档，正文合计不少于 1 MB，并且除总耗时之外单独断言用户被阻塞等待的总时长——首次建索引期间阅读与捕获必须可用，那段时间不算阻塞。

**Blocked by:** 32, 34, 36

**Status:** ready-for-agent

**Starting failing test:** 从空知识库开始，用三份正文合计不少于 1 MB 的真实来源文档走完上述十个环节，断言最终导出的 Markdown 中含有指向至少两份不同来源文档的脚注、不含任何编辑期标色或标签、且正文中每一处引用都能解析回一条真实存在的思想笔记；断言整条路径在参考机型画像上的挂钟耗时低于三十分钟，其中用户被阻塞等待的总时长低于五分钟。

**Demo acceptance:** 需要。这张票同时承接 spec 的元目标——首个版本能不能作为所有者的日常个人工具真正用起来。这只能由人走完这三十分钟后回答，不能由任何断言回答。

- [ ] 存在一个端到端测试，在单次运行内串起首次运行配置、导入、渐进索引、阅读选中、捕获、主题发现、提案审阅、正式写作、归属检视与干净导出
- [ ] 场景使用三份正文合计不少于 1 MB 的真实来源文档，而非微型素材
- [ ] 测试断言导出物含指向至少两份不同来源文档的脚注
- [ ] 测试断言导出物不含任何编辑期标色与标签
- [ ] 测试断言导出物中每一处引用都解析回一条真实存在的思想笔记，而不是悬空引用
- [ ] 测试断言整条路径挂钟耗时低于三十分钟
- [ ] 测试断言用户被阻塞等待的总时长低于五分钟，首次建索引期间阅读与捕获可用因而不计入阻塞
- [ ] 实测耗时被记录在案，作为后续回归的基线；记录基线不得用于放宽上述两个上限
- [ ] 人工验收覆盖「这个版本能否作为日常个人工具使用」这一判断，并把结论写进本票
