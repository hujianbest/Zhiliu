# 28: 早期贯通场景（导入到检索）

**What to build:** 一条把前半条链真正串起来的端到端场景。到这一层为止，每张票都只断言了自己范围内的行为，票与票之间的接缝——票 08 捕获出来的笔记标识能不能被票 09 的检索认出、票 16 感知到的外部编辑能不能反映到票 12 的索引里、票 09 返回的出处能不能跳回票 04 导入的那份来源文档——从未被任何断言穿过一次。这张票就是那一次穿越。

它排在这里而不是等到末尾，是因为接缝坏了应该在第九层就知道，而不是在第十四层。创作链与导出的接缝由票 41 承接。

**Blocked by:** 12, 16

**Status:** done

**Starting failing test:** 在一次测试里从空知识库连续走完：首次运行选择知识库 → 导入一份 EPUB → 打开阅读并跳到某一章 → 选中一段文字捕获为思想笔记 → 在应用外用文本编辑器修改这条笔记的想法字段 → 断言应用无需重启即反映 → 用修改后的新措辞检索 → 断言命中该笔记 → 从结果跳回来源出处 → 断言落在导入的那份来源文档的该章节。每一环的产物必须被下一环真实消费：捕获产生的稳定标识出现在检索结果中，检索结果的出处解析回导入时复制进知识库的那个文件。

**Demo acceptance:** 需要。这条路径连不连贯、有没有断裂感，只有人走一遍才知道。

- [x] 存在一个端到端测试，在单次运行内串起首次运行、导入、阅读、捕获、外部编辑、增量索引、检索与跳源
- [x] 测试断言捕获产生的稳定标识确实是检索结果中的那一个，而不是各自独立地都存在
- [x] 测试断言检索结果的出处能解析回知识库内的来源文件并定位到正确章节
- [x] 测试断言外部编辑后的新措辞可被检索命中、旧措辞不再命中
- [x] 整条路径不需要任何模型调用，因此可在无凭据、断网条件下运行
- [x] 这条场景与它断言的接缝被记录下来，后续票新增接缝时在此扩展而不是另开一条平行场景
