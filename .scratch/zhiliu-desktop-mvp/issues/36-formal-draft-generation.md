# 36: 正式稿生成

**What to build:** 通过就绪检查的提案生成一份正式稿并进入创作编辑器，稿件只使用用户确认纳入的证据，并按三值来源归属标注每段文字。正式稿与试写稿在界面上有明确区分。当某条被引用的思想笔记后来被用户删除时，稿件正文绝不被自动改动，那条引用转为显式的「证据已失效」状态，因此来源清单不会悄悄变短。

**Blocked by:** 33

**Status:** done

**Starting failing test:** 确认一份提案并生成正式稿，断言稿件只含勾选的证据；随后删除其中一条被引用的思想笔记，断言稿件正文未被改动而该引用显示为证据已失效。

**Demo acceptance:** 需要。生成稿的可用程度与失效提示的清晰度需要人判断。

- [x] 写作就绪的提案可以生成一份正式稿并进入创作编辑器
- [x] 稿件按三值来源归属标注每段文字
- [x] 稿件只使用用户确认纳入的证据
- [x] 正式稿与试写稿在界面上有明确区分
- [x] 被引用的思想笔记被删除时，稿件与提案正文不被自动改动，该引用转为显式的证据已失效状态——自动改写正文会让来源清单静默变短，而这正是来源归属要防的事
- [x] 「需要修复」状态的笔记同样使引用转为证据已失效，修复后引用恢复有效（承接票 16）
- [x] 生成过程留下完整的生成留痕
- [x] 生成失败时提案与已确认的选择不丢失
