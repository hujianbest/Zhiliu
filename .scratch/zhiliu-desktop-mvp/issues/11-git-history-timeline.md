# 11: 自动 Git 提交与应用内历史时间线

**What to build:** 知识库的变化自动形成可回滚的历史，用户在应用内看到的是一条友好的操作时间线，不需要任何命令行知识即可回到之前的状态。追踪范围限于 Markdown 知识与轻量元数据，来源文件二进制、索引与缓存被忽略，历史因此保持可用。高级用户仍可用外部 Git 工具查看同一仓库。

**Blocked by:** 02, 04, 08

**Status:** done

**Starting failing test:** 捕获一条笔记后断言产生一次提交、且已导入的来源文件二进制未入库；再改这条笔记，从时间线回滚并断言文件内容与索引都回到之前状态。

**Demo acceptance:** 需要。时间线的措辞是否让不懂 Git 的人看懂，只能人判断。

- [x] 记录 Git 集成方式与追踪边界的 ADR
- [x] 自动提交的追踪范围声明为：Markdown 知识、主题、提案、风格档案、稿件、提示词覆盖与轻量关系元数据。本票只断言笔记这一类，其余各类的断言随其实体诞生：主题在票 22、提案在票 33、稿件在票 24、风格档案在票 39、提示词覆盖在票 25
- [x] 来源文件二进制、本地模型、索引、日志与缓存被忽略
- [x] 忽略规则中保留 OCR 产物一条，为将来的 OCR 预留；本版本不产生这类目录，实现者不必去找（ADR-0009）
- [x] 应用内历史时间线以友好语言展示操作，用户可在界面内回滚到之前状态
- [x] 回滚后应用内视图、索引与文件状态一致
- [x] 高级用户可以用外部 Git 工具打开同一仓库查看提交
- [x] 不提供分支管理、交互式 rebase、远端托管等完整 Git 客户端功能
