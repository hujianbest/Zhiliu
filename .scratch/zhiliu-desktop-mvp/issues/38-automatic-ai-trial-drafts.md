# 38: 自动 AI 试写稿

**What to build:** 用户打开应用就能看到一篇已经写出来的东西：满足写作就绪的思想线索会在后台预算内自动生成完整试写稿，显著标注为推测性的 AI 产物。书库发现只产生提案，不自动生成完整稿件，主动生成因此始终贴着用户自己的思考。试写稿不能原地转正：它最多预填一份提案，用户确认后生成的是一份新的正式稿，试写稿本身作为历史保留。

「界面上不存在原地转正的入口」这句话不能作为断言——实现之前界面不存在，它天然通过。可断言的形式是正向的：从试写稿出发的唯一路径产出一份新的正式稿，而试写稿在此之后仍以原内容与试写种类存在。

**Blocked by:** 21, 36

**Status:** done

**Starting failing test:** 让一个思想线索在后台预算内自动出稿，断言产物的种类为试写且显著标注为 AI 推测；从它走完唯一的转正路径，断言产生一份新的正式稿而试写稿仍以原内容与试写种类存在；断言书库发现只产生提案；断言试写稿在任何状态下都不被检索召回。

**Demo acceptance:** 需要。试写稿的标注是否足够显眼、内容是否值得一读，只能人看。

- [x] 只有满足写作就绪的思想线索会自动生成完整试写稿
- [x] 书库发现只产生提案，不自动生成完整稿件
- [x] 试写稿显著标注为推测性的 AI 产物
- [x] 试写稿永远是试写+草稿组合，不存在试写+定稿（ADR-0003）
- [x] 试写稿永不进入检索语料，无论其状态如何（ADR-0011）
- [x] 从试写稿出发的唯一路径是预填一份提案，用户确认后生成一份新的正式稿；试写稿在此之后仍以原内容与试写种类存在（ADR-0003）
- [x] 界面呈现试写稿与由它派生的正式稿之间的关系，不让两者看起来像重复内容
- [x] 自动生成受后台预算约束，预算耗尽时不再生成
- [x] 用户打开应用即可看到已生成的试写稿
