# 16: 应用内 Markdown 编辑与外部编辑监听

**What to build:** 用户既可以在知流内直接编辑笔记，也可以用 Obsidian 或 VS Code 编辑同一批文件；在应用外做的修改无需重启就会出现在知流里，索引增量刷新。外部编辑破坏了稳定标识时，应用把该文件隔离出来请用户修复，而不是悄悄换一个新标识把引用链断掉。

**Blocked by:** 08, 12

**Status:** ready-for-agent

**Starting failing test:** 应用运行时在外部改一条笔记，断言无需重启即反映；再在外部删掉某条笔记的稳定标识，断言该文件被列为「需要修复」且没有被重新分配标识。

**Demo acceptance:** 需要。「需要修复」的提示是否让人明白该怎么做，只能人判断。

- [ ] 应用内可以编辑笔记 Markdown 并保存
- [ ] 在应用外修改知识库文件后，应用无需重启即反映变化并增量刷新索引
- [ ] 在应用外新增或删除知识库文件同样被感知
- [ ] 稳定标识被外部编辑删除、损坏或造成重复时，该文件被拒绝纳入检索语料与全部 Agent 工作并列为「需要修复」，应用绝不静默重新分配新标识（ADR-0013）
- [ ] 标识重复时两份文件都被隔离，应用不假定哪一份是原件，由用户选择（ADR-0013）
- [ ] 「需要修复」的文件提供修复入口，修复之后指向它的笔记关系仍然有效（提案与稿件引用在本票时点还不存在，该项断言由票 33 与票 36 补充）
- [ ] 其他非法或不完整的外部产物同样被校验并给出可读提示，索引不被破坏
- [ ] 端到端测试在应用运行时用外部方式修改文件并断言刷新
