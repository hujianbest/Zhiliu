# 稳定自签证书的保管、导出与恢复

macOS 发行包必须用**同一张**自签证书签名，否则系统把每次发版当成不同身份，知识库文件夹的访问授权会在升级后失效，而「系统设置」仍显示已授权（ADR-0010）。这张证书是长期项目机密。它**不得**进入本仓库、不得进入知识库、不得放进用户机器的凭据库。

丢失私钥 = 所有现有用户必须重新授予文件夹访问权限。没有第三种结果。

## 证书本身不在本仓库

仓库只记录流程。证书与私钥只存在：

1. **构建机登录钥匙串**（长期使用的那一台打包 Mac）
2. **仓库之外的离线加密备份**（另一块加密盘或离线密码管理器的附件，不是 Git LFS，不是 CI 日志）

## 在构建机上安装

1. 若尚未创建：用钥匙串访问生成一张代码签名自签证书，常用名称固定为 `ZHILIU_CODESIGN_IDENTITY` 将使用的字符串（例如 `Zhiliu Self-Signed`），哈希算法与密钥长度按当前 Apple 代码签名要求，有效期按项目生命周期拉长，避免中途换证。
2. 把证书装进**登录**钥匙串，允许 `codesign` 在无 UI 时访问（构建机专用；不要在日常使用的笔记本上对所有应用开放私钥）。
3. 导出前先确认 `security find-identity -v -p codesigning` 能看到这张证，且后续两次构建的 `codesign -dv --verbose=4 知流.app` 中 `Authority` 与团队/标识一致。

构建时设置其一：

- `ZHILIU_CODESIGN_IDENTITY`：钥匙串中的常用名称
- 或 `CSC_LINK` + `CSC_KEY_PASSWORD`：指向 p12 的路径（CI 用；p12 仍不进仓库）

`npm run pack:mac` 在两者都缺失时**直接失败**，不会退回 ad-hoc 签名。

## 导出（做离线备份时）

1. 打开钥匙串访问，选中该证书及其私钥。
2. 导出为 `.p12`，设置一个只有构建负责人知道的口令。
3. 把 `.p12` 放到仓库之外的加密介质。不要提交、不要放进 Issue 附件、不要放进知识库备份。
4. 另存一份当前常用名称与证书 SHA-1/SHA-256 指纹的明文记录（可以进内部运营文档，仍不要进本 Git 仓库），以便恢复后核对是同一张证。

## 恢复路径

1. 在新构建机上双击 `.p12` 导入登录钥匙串，输入导出时的口令。
2. `security find-identity -v -p codesigning` 确认常用名称未变。
3. 设置 `ZHILIU_CODESIGN_IDENTITY` 为同一字符串。
4. 打一个测试包，用 `codesign -dv --verbose=4` 比对指纹与备份记录。不一致就停，不要发版。

## 丢失之后

没有用备份恢复的办法时，必须签发**新**证书。此后每一次用户升级都会丢掉旧的文件夹访问授权，需要在发行说明里写明「这次升级会要求重新允许知流访问知识库所在的文件夹」。不要假装授权还在。
