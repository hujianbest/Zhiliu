# 端到端断言范围

这条规则是后续所有票的先例。知流的质量闸门是 Playwright 驱动**打包后的** Electron 二进制。断言只覆盖两件事：

1. **用户可见行为**：窗口里能看见、能点、能键入、能读到的文案、控件状态与导航结果。
2. **磁盘上的持久产物**：知识库里的 Markdown、目录布局、忽略规则、阅读进度、导出物等用户可以拷走或用外部工具打开的文件。

不要断言：

- 私有组件结构、CSS 类名是否存在、内部模块如何拆分
- 内部方法是否被调用、函数调用次数、私有事件总线
- 具体数据库查询语句、索引内部行格式
- 提示词空白、模型温度等实现细节
- 偶然的文件顺序，除非规格要求稳定排序
- Playwright 选择器所依赖的实现细节（用角色、可访问名称与可见文本，而不是内部 id 冒充规格）

允许检查**主进程状态**，前提是它回答用户可感知的问题，例如：当前知识库路径是不是这次运行注入的临时目录、假 OpenAI 服务是否收到了这次调用、打包应用的 `utilityProcess` 是否还活着。不要借「主进程状态」去窥视私有协作对象。

打包二进制必须保持 `EnableNodeCliInspectArguments` fuse 启用，否则本套件启动会静默超时。CPU 密集任务一律走 `utilityProcess`，不进 `worker_threads`（见 `docs/adr/0022-utility-process-for-cpu-work.md`）。
